# M0-04 한글 IME · 렌더러 검증 (리스크 선검증)

- 마일스톤: M0 스캐폴드 · 의존: M0-03
- 이 기능은 코드를 만드는 것보다 **검증하고 결정을 기록하는 것**이 목적이다. 결과는 M1-02, M3-02에서 쓴다.

## 목표
MVP에서 가장 큰 기술 리스크 두 가지를 기능 개발 전에 확인하고, 대응 방법을 확정한다.

## 할 일
- [ ] **한글 조합 입력**: pwsh 프롬프트와 `claude` 안에서 "안녕하세요 한글 입력 테스트"를 입력해서 조합 중 글자 중복 · 누락 · 커서 튐이 없는지 확인
- [ ] 조합 중 Backspace, 조합 중 방향키, 조합 중 Enter 동작 확인
- [ ] **한글 출력 폭**: `unicode11` 적용 후 한글 · 이모지가 섞인 출력의 정렬 확인 (`ls`, 표 출력)
- [ ] **WebGL 컨텍스트 한도**: 터미널 20개를 만들어서 컨텍스트 소실이 언제 나는지 확인 (WebView2 기준 약 16개로 알려짐)
- [ ] 컨텍스트 소실 시 DOM 렌더러로 자동 폴백하는 정책 결정 → "보이는 pane만 WebGL" 등
- [ ] 문제가 있으면 우회책 확정 (xterm 버전 고정, 옵션, composition 이벤트 패치 등)

## 작업 기록
- 2026-10-19 (준비만 완료, 체크박스는 직접 실행 후 체크): IME 조합 입력은 GUI에서 한글 키 입력이 필요해서 자동으로 확인할 수 없다.
  - 현재 `TerminalPane`은 Unicode11 활성, WebGL 로드, `onContextLoss` 시 애드온 dispose → DOM 렌더러 폴백까지 이미 들어 있다.
  - 검증 도구: 개발 모드에서 `?stress=20`을 붙이면 터미널 N개 + "WebGL n · DOM 폴백 m" 카운터가 뜬다 (`App.tsx`, `TerminalPane`의 `onRenderer` prop). `pnpm tauri dev` 후 주소에 쿼리를 붙이거나 `App.tsx`에서 임시로 값을 지정해서 확인.
  - 남은 것: IME 항목 직접 입력 테스트, 20개 스트레스 결과 기록 → "보이는 pane만 WebGL" 정책 필요 여부 결정 → M1-02 반영.
- 2026-10-19 사용자 직접 확인: 한글 조합 입력(pwsh, claude)과 한글 출력 폭은 문제 없음. 스트레스 테스트는 `claude`가 정상 실행된다고만 확인했고 DOM 폴백 개수는 기록하지 않았다.
  - 결정(기본안): 컨텍스트 소실 시 해당 pane만 DOM 렌더러로 자동 폴백(현 구현 유지). "보이는 pane만 WebGL"은 실사용에서 폴백이 눈에 띄면 그때 추가.
